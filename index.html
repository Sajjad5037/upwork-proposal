Initial hypothesis (to be validated)

Some routing logic may be embedded in the agent prompt, while differences between board structures or how existing items are processed may contribute to inconsistent behavior. I would inspect the implementation, workflow charts, configuration, and logs before confirming the root cause.

How I would approach the project

Start with evidence, fix the highest-impact causes, and test before changing live workflows.

Phased implementation

Audit & reproduce

Compare the current implementation with your workflow charts and reproduce reported failures to locate the causes.

Make routing configurable

Move business rules from the agent prompt into a centralized configuration the project manager can edit safely.

Standardize routing

Test distinct rules for long-form content, trailers, clips, shorts, and thumbnails, including both reviewer phases per client.

Backfill existing items

Apply current rules to eligible in-progress items in controlled batches, preserving valid progress and avoiding duplicate updates.

Add observability

Log decisions, rules applied, API outcomes, and failures; add appropriate error handling, monitoring, and recovery.

Deploy & document

Move to suitable cloud hosting and provide SOPs for adding clients, changing workflows, and troubleshooting issues.

Design principle: separate interpretation from execution.

The AI can interpret a Slack message, while explicit, testable logic handles routing and validates monday.com updates. This makes behavior more consistent across boards, reduces errors, and makes failures easier to debug.
